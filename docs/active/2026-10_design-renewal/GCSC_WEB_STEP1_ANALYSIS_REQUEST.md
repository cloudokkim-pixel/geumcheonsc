- 대상 최신본: https://geumcheonsc.vercel.app/
- 목적: 서비스 소스를 수정하기 전에 대표 구간의 실제 구조·보존 기준·최소 수정 범위와 검증 방법을 확인한다.
- 이번 종료점: 결과 MD 제출 후 중단. STEP 2 구현은 이 대화에서 결과 검토 후 요청한다.

## 1. 작업 경계

이번에는 읽기 중심으로 조사한다. 서비스 소스·CSS·자산·설정·DB·의존성·lock 파일을 수정하지 않는다. 설치·마이그레이션·자동 수정·리팩터링·커밋·푸시·배포를 실행하지 않는다. 기존 작업 트리의 사용자 변경을 되돌리거나 섞지 않는다.

예외적으로 **이번 결과 MD 1개와 현행 화면 캡처**의 신규 작성만 허용한다. 기존 파일을 덮어쓰지 말고, 같은 결과 파일이 있으면 그 사실을 보고하고 별도 이름으로 제출한다. 서버 실행에 설치나 설정 변경이 필요하면 실행하지 말고 제약을 기록한다. 로컬 화면이 필요한 경우 기존 실행 환경을 활용하며 실제 신청·문의·후원 데이터를 전송하지 않는다.

관리자 리뉴얼은 제외한다. 공통 스타일이 관리자에도 연결돼 있는지는 의존 관계만 확인하고, 관리자 업무·API·권한·DB 조사는 확장하지 않는다.

## 2. 적용 자료와 우선순위

저장소에서 다음 두 파일을 한 번 찾아 읽고, 실제 위치를 결과에 기록한다. 정리 위치가 필요하면 `docs/design/gcsc/`를 권장하지만 이번 단계에서 원본 파일을 이동하거나 수정하지 않는다. 자료가 없으면 누락 파일을 명시하며 가이드를 추정해 대체하지 않는다.

1. `01_GCSC_공통디자인기준_v1.3.html`
2. `02_GCSC_홈페이지디자인기준_v1.3.html`

`03_GCSC_관리자디자인기준_v1.3.html`은 이번 적용 대상이 아니다. 보존 부록의 과거 약자·색 제한·카드 강조선 규칙을 현행 규칙으로 재적용하지 않는다.

리더의 이번 명시 결정 → 가독성·필수 정보·조작 기준 → 공통 기준 → 홈페이지 기준 순으로 해석한다. 충돌은 근거·범위·상태를 기록한다. 가이드의 크기·간격·높이·모션 수치는 시안 검증용 제안이며, 자동 확정값이 아니다. 가이드 자체 문서의 장 제목 규격을 서비스 화면에 일괄 적용하지 않는다.

## 4. 필요한 조사만 수행

1. 적용되는 `AGENTS.md`, 현재 작업 트리, 프레임워크·실행 스크립트를 확인한다. 현재 변경 파일은 내용 노출 없이 경로·상태만 기록한다.
2. 메인 페이지, 헤더/모바일 메뉴, 언어 선택, 공통 CSS·폰트, 히어로, 운영 정보, 배경 엠블럼, 공유 레이아웃의 **직접 관련 파일**을 찾는다. 읽은 파일과 역할을 간결히 기록한다.
3. 엠블럼·대표 사진의 원본 위치, 외부/내부 경로, 크기·비율·색 처리, 이미지 로딩과 배경 레이어 구조를 확인한다. 사진 권한은 소스에 없으면 미확인으로 둔다.
4. 아래 구성·기능을 실제 소스와 대조해 보존 기준을 만든다. 화면에서 보았다는 사실과 실제 운영 사실·데이터 근거를 구분한다.
5. 대표 구간의 현재 서체·크기·굵기·행간·간격·배경·대비·선·모서리·높이를 확인하고, 관련 가이드 조항과 대조한다. 실행하지 못하면 코드상 값과 화면상 미검증을 구분한다.
6. 공유 헤더·전역 스타일 변경이 다른 공개 페이지와 관리자에 미칠 영향을 확인한다. 대표 구간에 한정할 스타일 범위를 제안한다.
7. STEP 2의 최소 수정 파일, 예상 변경, 보존 항목, 검증 명령·화면 조건을 제안한다. 추가 라이브러리나 새 디자인 시스템을 도입하지 않는다.

## 5. 검증 방법

### 이번 STEP 1에서 할 검증

- 조사 전후 작업 트리와 diff를 비교해 **서비스 소스·설정·자산 변경 0건**을 확인한다. 결과 MD·캡처 신규 파일과 기존 사용자 변경은 분리한다.
- 기준 경로와 실제 파일·참조를 대조하고, 추정 파일명·존재하지 않는 기능을 확정하지 않는다.
- 가능하면 현행 1280×900과 390×844에서 헤더·첫 화면·운영 정보·다음 섹션 경계가 보이는 캡처를 남긴다. 로컬/배포본·URL·뷰포트·캡처 조건을 적는다. 불가 시 이유와 미검증 항목을 남긴다.
- 빌드·테스트는 기존 명령과 대상만 확인한다. 이번 조사에서는 설치·전체 빌드·서비스 데이터 전송을 하지 않는다.

### STEP 2 요청에 반영할 검증 계획

- 폭 320·390·430·768·1280·1920px, 각 실제 높이 기록. 1280×900·1920×1080 및 대표 모바일 화면을 포함한다.
- 변경 전후 문구·값·자산·href·쿼리·기능 비교, 공통 스타일의 범위 밖 영향 확인.
- 밝고 어두운 구간의 엠블럼 인지·연속성·원본 보존·실제 배경 합성 대비 검사.
- 200% 확대, 키보드·포커스·메뉴 닫기/복귀, 모바일 조작 영역, 긴 문구·사진 실패·감소 모션 검사.
- 제목·CTA 즉시 사용, 불필요한 반복 연출 없음, 페이지 가로 넘침·잘림·겹침 없음.
- 실제 사용 가능한 빌드·기존 관련 검증만 수행. 실패·미검증·기존 오류를 구분한다.

**기준 검수와 구현 검수는 별도 열로 작성한다.**

`항목 | 가이드 조항·상태 | 현행 코드값 | 실제 화면 근거·조건 | 차이·제안 | 판정`

판정은 `통과 / 미통과 / 미검증 / 해당 없음`. 기준 문구가 있다는 이유만으로 실제 구현을 통과 처리하지 않는다. 정량 대비는 배경 엠블럼·사진·투명도를 합성한 상태에서 검사하며, 이번에 측정하지 못했으면 미검증으로 둔다.

## 6. 결과 제출

`docs/handoff/GCSC_WEB_STEP1_ANALYSIS_RESULT.md` 1개를 작성한다. 해당 경로가 저장소 규칙과 충돌하면 기존 문서 위치를 따르고 실제 제출 경로를 명시한다.

결과에는 다음을 간결하게 포함한다.

1. 결론·수정 여부·검증 수준·제약.
2. 관련 파일/역할, 공유 영향, 확인한 가이드 실제 경로.
3. 콘텐츠·기능·자산·연결 경로 보존 목록. 긴 원문을 반복하지 말고 소스 위치로 추적 가능하게 기록.
4. 엠블럼 레이어 현황과 밝은 면에서도 이어지는 최소 변경 제안.
5. 대표 구간의 기준/실제 이중 대조표, 현행 캡처 경로·조건.
6. STEP 2 수정 파일·범위·유지 항목·검증 계획 및 결정이 필요한 항목.
7. 실행한 명령과 결과, 실제 소스 변경 0건 근거, 신규 결과물 목록, 미검증·미확인 목록.

이 요청의 완료는 소스 조사 완료이며, 대표 구간 구현 완료가 아니다. **결과 제출 후 멈추고 STEP 2를 자동 시작하지 않는다.**

## 7. 토큰 사용 원칙

관련 파일부터 탐색하고 가이드 전문·소스 전체·대용량 로그를 결과에 복사하지 않는다. 의존성·생성 파일·전체 DB·관리자 내부로 탐색을 넓히지 않는다. 결과 문서를 다음 단계의 구조 인덱스로 재사용한다. 별도 검증 요청문서는 만들지 않는다. 문맥 제한이 가까우면 확인된 파일·결정·미완료 항목만 결과에 기록하며 무제한 재탐색하지 않는다. 토큰 수는 도구가 제공하는 실제 계측값이 있을 때만 보고한다.
